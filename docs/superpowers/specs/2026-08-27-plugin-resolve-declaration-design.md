# 插件声明的主动取回 设计方案

**日期**：2026-08-27
**涉及仓库**：legionAgent（服务端）、legionAgentGUI（界面）
**前置**：GUI 授权同意流已交付并合入（server #87 / GUI #22 / docs #8）

## 要解决的问题

一条**未缓存的远程插件**目前在 GUI 里是死路：同意对话框在 `declared_unresolved` 为真时禁用确认按钮，因为没有声明可以展示；而运维在面板上没有任何办法把声明取回来。结果是这类插件**只能经 CLI 授权**。

一个容易走错的方向是「消掉 GUI 那条规则」。不能这么做，因为**那条规则是对的**：不能让人对一份看不见的清单点同意，这正是整期同意流的立意。真正缺的不是放宽，而是**给它一条出路**——让运维能主动把声明取回来看见，然后在看得见的前提下做决定。

同样值得先说清的是：**服务端并没有缺口**。`PluginConsentService.Grant` 本来就会在缓存未命中时下载（`resolvePluginPackageDir`），CLI 因此能授权未缓存的远程插件。缺的只是「让 GUI 能看见声明」这个手段。

## 一、让「不可信」能被认出来

`verifyManifestSignature`（`internal/plugin/manifest/assemble.go:139-156`）今天有四条失败路径，全部是 `fmt.Errorf` 字符串包装，`errors.Is` 认不出任何一条。要把「拿不到」和「拿到了但不可信」分开呈现，类型必须先能表达这个区别。

新增哨兵 `manifest.ErrUntrustedPackage`，挂在**三条**路径上：

| 路径 | 挂哨兵 | 理由 |
|---|---|---|
| `plugin.sig` 缺失 | 是 | 部署要求签名而包没有——这个包不可信，重试无用 |
| `plugin.sig` 解析失败 | 是 | 签名文件本身是坏的 |
| `keyring.Verify` 失败 | 是 | 核心验签不通过 |
| 读 `plugin.sig` 的 I/O 错误 | **否** | 磁盘或权限问题，属于「拿不到」，重试有意义 |

第四条刻意排除。它与源站超时同类，是环境问题不是信任问题；把它归进安全告警会让真正的安全事件贬值。

这是本仓第三次为「两件事需要分开，而类型表达不了」加哨兵：前两次是 `taskgate.ErrBoundaryNotReached`（收敛从未发生 vs 收敛失败）与 `Entry.GrantStated`（从未授权 vs 决定过又撤销）。

## 二、端点：只取回，不授权

`POST /v1/plugins/{name}/resolve`

用 POST 不是因为它改变状态——它不碰授权——而是因为它**有副作用**：发起出站请求、往缓存目录写盘。GET 不该做这些，这正是 `List` 当初拒绝在缓存未命中时 fetch 的理由（见 `plugin_consent_service.go` 对 `resolveDeclaredPackageDir` 的说明）。

复用既有链路，不新造任何一步：

```
resolvePluginPackageDir（fetch + 解包，摘要把守）
  → LoadPackage（验签）
  → 读声明
```

与 `Grant` 完全同路，**只是到此为止**：不碰 `plugins.json`，不写 `grant` 段，不触发收敛。

**返回体是现成的 `PluginView`**，不新增 DTO。成功时 `declared_unresolved: false` 且三个 `declared_*` 填满，GUI 拿到直接替换那一行。

### 三条不变量

| 不变量 | 理由 |
|---|---|
| `plugins.json` 一字节不动 | 取回只是「看清楚」。运维可以取回完就走人，不留任何授权痕迹 |
| 沿用 `install`/`grant` 的全部前置检查 | 明文 `http://` 未开则拒、缓存未配置则拒。绕过它们等于开了第二条拉包路径 |
| 缓存命中时不联网 | 复用 `Cache.Has`，重复点按钮不会反复下载 |

### RBAC：`write_plugin`

按**副作用**分类，而不是按「改没改授权」分类。它让服务端发出站请求、往磁盘写文件——只读角色不该能驱动服务器去下载东西。沿用既有的 governance 模式：`policy.Allows` → 拒绝时 `auditRBACDenied` → 403，且这三步都在 `plugins == nil` 检查**之前**（与 `handleListPlugins` 一致，顺带不向无权限者泄漏这个部署有没有开插件）。

### 一处有意接受的副作用

取回成功后包**留在缓存里**，即使运维最终决定不授权。这是有意的：它正是让后续 `grant` 不必再下载一次的原因，也与 CLI 行为一致。digest 是内容寻址的，同一个包不会重复占空间。

**这件事必须在 UI 上说明**，不能无声发生。见下节。

## 三、界面

### 未取回

那一行多一个按钮，与「授权」并列但用**次要样式**——取回不是目的，授权才是：

```
legion-jira                                    [未授权]
声明尚未在本地解析（远程包未缓存），无法确认它请求的范围
[取回声明]  [授权(禁用)]
```

「授权」保持禁用不变。那条规则不动。

### 取回中

按钮转圈禁用。这一步会真的下载，**必须走 `beginPluginConsent` / `endPluginConsent`**，否则 `SettingsModal` 的 Escape / 标题栏 X / 背景点击三道关卡看不见它——运维一按 Esc 就能关掉窗口而服务端还在下载。上一期终审逐扇门堵过这个洞，新入口不能重新打开它。

### 取回成功

那一行原地换成带声明的状态：`declared_*` 填满、「授权」解禁。同时**常驻**一句说明（不是几秒即逝的提示，因为这个事实持续为真）：

> 已取回并缓存该插件包（未授权，可随时撤销）

### 取回失败：两条岔路

第一节的哨兵在这里兑现。

| 失败类别 | 呈现 |
|---|---|
| 拿不到（网络 / 摘要 / 策略 / 缓存未配） | 普通错误文案 + **[重试]** |
| 拿到了但**不可信**（三条签名路径） | 醒目告警样式，**没有重试按钮**，文案点明这个包的签名不被信任、重试无用、需要联系包的提供方 |

第二类不给重试是刻意的，与上一期「收敛等待期间没有取消按钮」同源：**一个按下去必然无效的控件，就是在骗人**。

## 四、测试

### 服务端

| 要钉住的 | 怎么钉 |
|---|---|
| 哨兵挂对三条、漏掉第四条 | 四条路径各一个用例；前三条 `errors.Is` 命中，I/O 那条**不**命中 |
| 取回不动 `plugins.json` | 取回前后文件**字节比对** |
| 缓存命中不联网 | 先取回一次，**关掉 `httptest.Server`**，再取回——第二次仍成功。任何意外的第二次 fetch 都会 connection-refused 而非静默通过 |
| 前置检查 | 明文未开、缓存未配各一个拒绝用例 |
| RBAC | 只读角色 403，**且审计落到**（上一期发现审计代码写对了却没有测试钉住） |

### 界面

- 签名失败**没有**重试按钮——负向断言，防止后来者出于好意加回来
- 取回中三道关卡拦得住——**必须在 `SettingsModal` 里渲染**，不能独立渲染。上一期的教训正是 bug 住在集成缝隙里，而两个组件测试都是独立渲染，谁也看不见
- 缓存说明常驻

### 变异验证

每条守卫都要做：拿掉它，对应测试必须变红。

## 明确不做

- **批量「取回全部」**：一次点击引发 N 个出站下载，值得单独想清楚
- **缓存清理与容量上限**：既有待办，不在本期
- **不改 `unresolvedBlocked` 规则本身**：只给它出路

## 一处诚实的残留

取回后包留在缓存里，即使运维最终不授权。UI 会说明这一点，但**没有**「取回后反悔、把缓存清掉」的入口。加它就等于开始做缓存生命周期管理，超出本期范围。

## 改动面

服务端约三处：`manifest` 加哨兵、`PluginConsentService` 加 `Resolve` 方法、`internal/server` 加路由与 handler（并扩 `PluginConsent` 接口）。
界面约两处：`app_plugins.go` 加绑定、`PluginsPage.tsx` 加按钮与两种失败呈现。
